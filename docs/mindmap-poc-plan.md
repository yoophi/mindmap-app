# 마인드맵 PoC 구현 계획

## 범위와 완료 기준

- Tauri 데스크톱 앱에서 마인드맵 하나를 열고 편집한다.
- 노드를 선택하고 하위 또는 형제 노드를 추가한다. 제목을 바꾸고, 루트를 제외한 노드와 그 하위 트리를 삭제한다.
- 루트 가지를 중심선을 넘어 드래그해 좌우를 바꾸고, 노드는 같은 부모 아래에서 위아래로 드래그해 순서를 바꾼다. 다른 노드 위에 놓으면 해당 노드의 하위로 옮긴다. 드롭할 때 하위 트리와 연결선을 자동으로 다시 배치한다. 자기 자신이나 자기 하위 노드 아래로는 옮길 수 없다. 캔버스에서 이동·확대·축소·전체 맞춤을 할 수 있다.
- 네이티브 파일 대화상자로 문서를 저장하고 다시 연다. 취소, 읽기 실패, 잘못된 문서, 저장 이전의 문서 전환을 처리한다.
- 자체 버전 필드를 가진 `.mindmap.json`으로 저장한다. Classic 파일 가져오기, 교차 연결, 첨부, 동기화는 이후 범위다.

## 구조

- 독립 Git 저장소 안에 pnpm 모노레포를 구성한다. `apps/mindmap-app`과 Tauri 크레이트를 각각 pnpm 및 루트 Cargo 워크스페이스에 등록한다.
- React는 Feature-Sliced Design으로 구성한다. `app`은 앱을 연결하고, `pages/editor`는 화면을 구성하며, `features/edit-map`은 편집 상태와 동작을 조정한다. `entities/mind-map`은 문서 모델과 배치, 문서 저장 어댑터를 제공한다.
- Rust는 `domain`에 문서 모델과 유효성 검사를, `application`에 문서 포트와 열기·저장 유스케이스를, `infrastructure`에 JSON 파일 어댑터를 둔다. `inbound`는 Tauri 명령과 네이티브 파일 대화상자를 담당한다.
- 문서는 루트 ID와 부모 ID를 가진 순서 있는 노드 목록과 선택적 루트 가지 방향을 저장한다. 방향이 없는 기존 문서는 오른쪽으로 배치한다. 중복 ID, 고아 노드, 순환과 지원하지 않는 버전을 거부한다. 같은 디렉터리의 임시 파일에 저장하고 원자적으로 교체한다.

## 구현 및 검증 순서

1. 모노레포에 Tauri·Vite 앱을 등록한다.
2. React 트리 편집 화면, 자동 배치와 캔버스 이동을 구현한다.
3. Rust 저장·열기 명령과 화면을 연결한다.
4. 타입 검사, 프론트엔드·Storybook 빌드, Rust 테스트를 실행한다. 데스크톱에서 실제 파일 저장과 재열기를 확인한다.

## 실행

```sh
pnpm --filter @yoophi/mindmap-app tauri:dev
```
